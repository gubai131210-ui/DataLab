# ADR 0001：以 C++ 统计核心和项目化数据模型为基础

- 状态：已接受
- 日期：2026-08-13

## 背景

DataLab 面向汽车制造业质量工程师，需要支持可追溯的数据清洗、SPC、过程能力分析和报告输出。项目预计长期扩展算法、数据库、图表和报告能力，不能把统计逻辑直接放进 Qt 窗口代码。

## 决策

1. 核心质量算法使用独立的 C++ 模块实现。
2. 算法通过小而稳定的接口接收不可变输入，并返回结构化结果和诊断信息。
3. Qt 界面只负责交互和展示，通过应用层调用领域模块。
4. 原始数据与分析数据分离，原始数据保持只读。
5. 项目文件采用单文件 SQLite 容器，后续通过存储接口增加 MySQL 和 SQL Server 适配器。
6. Python 仅作为**开发/验证阶段**的独立工具脚本（如 Minitab fixture 转换），不作为应用运行时或核心质量指标的计算来源。

## 备选方案

### 全部使用 Python

开发统计能力较快，但核心结果依赖 Python 运行时和第三方库版本，不利于长期 Windows 部署与算法边界的统一控制。

### 全部写在 Qt 窗口类中

初期代码量较少，但会使界面、数据状态和算法互相耦合，难以测试和替换。

### 直接复用 LabPlot 或 Minitab 的实现

LabPlot 是参考项目，不等于可直接复用其全部实现；Minitab 是商业软件。直接复制会带来许可证、架构和产品定位风险。

## 后果

- 第一阶段需要先建立领域模型和算法测试边界。
- C++ 代码需要独立于 Qt 界面编译和测试。
- Python 辅助能力可以替换，而不改变核心统计结果接口。（Excel 导入已于 ADR 0006 移除运行时 Python 依赖。）
- SQLite 项目文件会成为未来审计、复现和报告的系统记录。
