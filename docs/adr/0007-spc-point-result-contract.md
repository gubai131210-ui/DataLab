# ADR 0007：SPC 逐点结果契约

## 状态

已接受

## 背景

控制图的绘制序号不是数据表原始行号。导入、缺失值、排除行、阶段切换和子组装配都会改变绘制点数量；如果在领域层重新使用 `0..n-1` 作为行号，图形刷选会选中错误的数据。

## 决策

每个控制图结果同时保存两套索引：

- `plotted_values` 的位置：用于控制限、窗口测试和绘图坐标；
- `source_rows`：用于回到 `DataTable` 的原始 `RowId`，允许一个子组点关联多个原始行。

特殊原因诊断保存逐点的 `triggered_tests` 和 `primary_test_by_point`。旧的 `test1_points`、`special_cause_points` 保留为兼容视图，由同一套测试结果生成。CUSUM 额外保存 `signal_direction`，其中 `1` 表示上侧、`-1` 表示下侧。

## 约束

1. `source_rows` 不得由领域算法使用 `iota` 重新生成。
2. 缺失或排除形成的断点不得跨越计算 MR、趋势和连续点测试。
3. 序列化必须允许旧 JSON 缺少新增字段；读取旧 payload 时新增集合为空。
4. `PlotSpec::source_rows` 继续作为图形刷选协议，新的逐点诊断字段只补充信息，不改变已有字段含义。

## 后果

输出表可以同时显示绘制序号和原始行号，悬停与刷选不会因数据装配而漂移。代价是子组结果需要保存一组原始行号，并且序列化 payload 增加版本兼容字段。
